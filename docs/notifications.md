# Напоминания UniFlow

## Локальная проверка

Запустите API и отдельный worker командой `pnpm dev`. В профиле включите «Напоминать о дедлайнах», укажите целое число минут от 1 до 10 080 и сохраните настройки. Для короткой демонстрации создайте открытое задание со сроком через несколько минут и смещением 60 минут. Worker создаст напоминание сразу после обработки задания, поскольку время планового оповещения уже прошло, а дедлайн ещё впереди. Для проверки ожидания выберите смещение одну минуту и дедлайн через две минуты.

В вебе и Android при открытом приложении входящие обновляются примерно каждые пять секунд. В профиле видны последние 30 напоминаний и число непрочитанных среди них. Баннер открывает нужное задание или позволяет пометить его прочитанным. Если на Android разрешены локальные уведомления, новое напоминание в открытом приложении также может появиться системным баннером. Закрытое приложение получит системное уведомление при настроенном внешнем канале и подписке конкретного устройства. Входящие сохраняются на локальном сервере и доступны при следующем открытии.

Настройки применяются к открытым личным заданиям и групповым заданиям текущих групп. В индивидуальном режиме завершение влияет на напоминания студента, который поставил отметку. В общем режиме закрытие останавливает напоминания всем. Позднее вступление в группу включает открытые задания с будущим дедлайном. Перед открытием задания приложение повторно проверяет доступ через API.

## Планирование и хранение

- Изменение дедлайна, выполнение, возвращение в работу, удаление, изменение настроек и членства обновляют ревизию соответствующей области. Ревизия и задача pg-boss фиксируются той же транзакцией, что и изменение данных.
- Worker вычисляет поколение напоминания из связанных ревизий, дедлайна и настроек. Уникальный ключ адресует получателя, вид задания, задание и поколение. При повторе или конкуренции появляется одна запись для каждого ключа.
- Выполнение и повторное открытие меняют поколение даже при сохранённом сроке. Перед записью во входящие и перед каждой внешней отправкой worker сверяет поколение, срок, состояние задачи, настройки и членство.
- Уже полученные напоминания остаются во входящих. Удаление задания или потеря доступа к группе скрывают связанные записи. История и недоступные подписки очищаются через 90 дней.
- Внешняя подписка привязана к сессии. Выход, отзыв сессии и её истечение отключают последующие отправки. Перепривязка устройства другому аккаунту обновляет владельца единственной записи для этого адреса.
- Ошибки `429` и ответы провайдера `5xx` допускают ограниченный повтор. Истёкшие адреса отключаются. После обрыва с неизвестным результатом или истечения активной попытки worker сохраняет неопределённый исход без повторной внешней отправки. Приём провайдером не гарантирует показ на устройстве.

## Внешний Android FCM

Для package `com.uniflow.app` нужен Firebase-проект с зарегистрированным Android-приложением, клиентский `google-services.json` и сервисный аккаунт с правом отправлять сообщения в этот проект. Укажите `GOOGLE_SERVICES_JSON` как путь к клиентскому файлу относительно `apps/client` или абсолютный путь и пересоберите Android. На сервере задайте `FCM_PROJECT_ID`, `FCM_CLIENT_EMAIL` и `FCM_PRIVATE_KEY`. Секрет сервисного аккаунта храните вне репозитория и не передавайте через переменные `EXPO_PUBLIC_*`. Сервер понимает `\n` в однострочной записи ключа.

При этих настройках в профиле Android появляется кнопка системных push. После разрешения приложение отправляет нативный FCM-токен. Worker использует OAuth и FCM HTTP v1. При нажатии системного уведомления приложение открывает задание. Профиль может отдельно запросить разрешение для локального показа при открытом приложении без Firebase.

Подключение и схема доставки описаны у поставщиков. [Expo Notifications с прямым FCM](https://docs.expo.dev/push-notifications/sending-notifications-custom/), [FCM HTTP v1](https://firebase.google.com/docs/cloud-messaging/send/v1-api).

## Внешний Web Push

Создайте постоянную пару VAPID-ключей. Например, в корне workspace можно вызвать генератор библиотеки.

```sh
pnpm --filter @uniflow/server exec node --input-type=module -e "import {generateVAPIDKeys} from 'web-push'; console.log(generateVAPIDKeys())"
```

Задайте на сервере `WEB_PUSH_PUBLIC_KEY`, `WEB_PUSH_PRIVATE_KEY` и `WEB_PUSH_SUBJECT` с контактным `mailto:` или HTTPS URL. Перезапустите API и worker. Используйте HTTPS или разрешённый браузером безопасный локальный контекст `http://localhost:8081`. В профиле включите системные push и выдайте разрешение браузеру. Service worker загружается с `/uniflow-notifications-sw.js` и принимает уведомления в этом origin.

API принимает HTTPS-адреса службы Google FCM для Chromium и Mozilla Autopush для Firefox. Другие браузерные службы требуют проверки совместимости и явного расширения списка. При смене VAPID-ключа переподключите устройства. Для проверки закрытой вкладки оставьте работающие API и worker, создайте задание с будущим моментом напоминания, закройте вкладку и откройте задание из системного уведомления. [Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API), [Web Push VAPID](https://github.com/web-push-libs/web-push).

Для системной доставки необходим Интернет и доступ к службе push. Реальную Android-доставку нужно проверить с учётными данными Firebase и установленной сборкой. Сценарий локальных входящих не требует Firebase, VAPID или удалённого сервера.
