Комплект описывает существующее приложение из `uniflow`. Функциональный код не изменялся. Формат сценариев — алгоритмические Use Case с альтернативами и результатом.

При передаче файлов вне репозитория приложите всю папку `technical-spec`: в ней находятся справочник API и копии макетов. Редактируемый интерфейс находится в Figma, PNG не заменяют файл Figma.

## Как показать работу

1. Открыть Word или PDF: назначение приложения, пользовательские алгоритмы, архитектура и безопасность.
2. Открыть Figma, страницу «01 Дизайн-система»: цвета, шрифты, размеры, компоненты и их состояния.
3. Перейти на «02 Экраны»: четыре рабочих экрана веба, вход и мобильный вариант. Проверить связь экземпляров с компонентами.
4. Открыть `api-reference.html` либо Swagger `/api/docs` при работающем локальном сервере.
5. При необходимости показать рабочее приложение по [инструкции локального показа](../local-demo.md).

## Обновление материалов

Скрипты не меняют приложение и не требуют его запуска. Для генераторов нужны Python 3, `python-docx`, Pillow; для DOCX → PDF и визуальной проверки — LibreOffice и Poppler. В среде Codex используются зависимости, найденные через `load_workspace_dependencies`.

Из корня проекта:

```sh
python3 docs/technical-spec/tools/build_api.py
python3 docs/technical-spec/tools/build_diagrams.py
python3 docs/technical-spec/tools/build_report.py
python3 docs/technical-spec/tools/validate_docs.py
```

`build_api.py` перечитывает сохранённый OpenAPI, не выполняя HTTP-запросов. Перед генерацией после изменения серверного контракта нужно отдельно обновить OpenAPI штатной командой проекта. `build_report.py` собирает Word из разделов 01–07 и копий макетов; полный автоматически генерируемый каталог API остаётся отдельным приложением, чтобы не дублировать его в отчёте.

На macOS генератор схем использует Arial из `/System/Library/Fonts/Supplemental`. На другой ОС замените `FONT_ROOT` на каталог с Arial и поддержкой кириллицы. PDF создаётся из итогового Word и проверяется после конвертации; скрипт генерации Word сам по себе не подтверждает вёрстку PDF.

## Проверка комплекта

Проверяются локальные ссылки, 36 уникальных UC, покрытие всех методов/схем OpenAPI, отсутствие устаревшего API-индекса, наличие двух страниц и шести экранов Figma по сохранённому описанию. Сам файл Figma дополнительно проверен средствами Figma: редактируемый текст, экземпляры компонентов, привязки токенов и отсутствие полноэкранных растров. Все страницы Word/PDF проходят отдельную визуальную проверку. Результаты проверок документации не подменяют прогон тестов приложения.
