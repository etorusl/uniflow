# Локальный показ UniFlow

Веб, API, worker, PostgreSQL, объектное хранилище и почта работают на компьютере, на котором проходит показ. Веб и Android используют одну базу. Для двух участников группы откройте разные браузерные профили либо войдите отдельными аккаунтами в вебе и Android.

## Запуск и остановка

Первую установку выполните по [основному README](../README.md#локальная-разработка). Если используется Colima, сначала запустите `colima start`. Команды ниже выполняются из корня репозитория.

```sh
pnpm infra:up
pnpm db:migrate
pnpm dev
```

Оставьте терминал с `pnpm dev` открытым. Веб доступен по адресу <http://localhost:8081>, почта для восстановления по адресу <http://127.0.0.1:8025>. При первом запуске нужно также выполнить `pnpm build:server` до миграций и `pnpm storage:init` до `pnpm dev`, как описано в README.

После показа остановите запущенные процессы и контейнеры. Том базы и хранилища при этом сохраняется.

```sh
pnpm android:emulator:stop
pnpm dev:stop
pnpm android:build:stop
pnpm infra:down
```

Если Docker работает через Colima и её VM больше не используется другими проектами, выполните `colima stop`. Для сервера, запущенного отдельно через `pnpm dev:server`, используйте `Ctrl+C` в его терминале.

## Самостоятельная Android-сборка

Требования к Android SDK, JDK и эмулятору перечислены в [README](../README.md#android). Сборка включает клиентский JavaScript и устанавливается как отдельное приложение `com.uniflow.app.local` рядом с development-версией `com.uniflow.app`. Для API используйте `EXPO_PUBLIC_API_URL=http://localhost:3000` либо другой локальный HTTP-порт. Открытое приложение продолжает обращаться к запущенному локальному серверу.

```sh
pnpm android:release
pnpm android:emulator
pnpm android:release:open
```

`android:release` создаёт подписанный `.local/uniflow-local-release.apk`. Скрипт генерирует локальный ключ подписи при первой сборке. Сохраните `.local/uniflow-local.p12` и `.local/uniflow-local-signing.key` приватно: этот же ключ нужен, чтобы устанавливать обновления поверх уже установленного APK. На эмуляторе ARM64 можно ускорить сборку с `UNIFLOW_ANDROID_ARCH=arm64-v8a pnpm android:release`.

`android:release:open` устанавливает APK и соединяет локальный порт API через ADB reverse. Если подключены несколько устройств, передайте `ANDROID_SERIAL`. Эта команда подходит и для Android-телефона с разрешённой USB-отладкой. Android использует сертификат самоподписанного APK только для проверки подписи при установке. HTTP разрешён в приложении для loopback-адресов.

Чтобы показать, что APK запускается самостоятельно, завершите `pnpm dev` и запустите `pnpm dev:server` в отдельном терминале. Откройте APK повторно. Это оставит API и worker работающими при выключенном Metro. Для показа веб-версии снова запустите `pnpm dev` после остановки отдельного `dev:server`.

Веб-сборку можно показывать одновременно с APK без Metro. Оставьте API и worker запущенными через `pnpm dev:server`, соберите и откройте готовые веб-файлы в другом терминале.

```sh
pnpm build:web
pnpm preview:web
```

Веб останется доступен по адресу <http://localhost:8081>. Остановите `preview:web` через `Ctrl+C` в его терминале.

## Сценарий показа

1. Войдите под первым аккаунтом и создайте учебную группу. Скопируйте приглашение. Войдите под вторым аккаунтом, откройте приглашение или введите код в разделе «Группы».
2. Создайте индивидуальное задание. Выполните его на втором аккаунте и сравните два статуса. Создайте общее задание и завершите его от автора, модератора или владельца. Посмотрите историю и сравните личный и общий прогресс.
3. Прикрепите небольшой документ или изображение к заданию. Опубликуйте материал в группе и проверьте доступ вторым аккаунтом. Выйдите из группы на втором аккаунте и обновите экран, чтобы увидеть потерю доступа.
4. В профиле включите напоминания. Для короткой демонстрации выберите опережение 60 минут и создайте открытое задание с дедлайном на несколько минут позже текущего времени. Планировщик ставит напоминание на ближайший момент, если номинальное время уже прошло, а сам дедлайн в будущем.
5. Дождитесь баннера «Напоминание о дедлайне» и откройте из него задание. В профиле проверьте входящие. Если приложение было закрыто, запись появится после следующего открытия. Локальный режим показывает оповещение внутри открытого приложения. Внешняя доставка в закрытый клиент использует настроенный push-провайдер.

Реальная доставка через Firebase и браузерный push настраивается отдельно. Для локального показа достаточно worker, работающего вместе с API.
