# Вложения и материалы групп

В разделе «Задания» кнопка «Вложения» открывает список файлов. Из группы доступны вложения отдельного задания и раздел «Материалы группы». Материал хранит название, описание и вложения. Его публикация не меняет дедлайны, отметки или статистику.

«Добавить файл» открывает системный выбор документа. «Добавить фото» фильтрует список по изображениям. В Android используется выбор уже сохранённого изображения. Веб скачивает файл, Android открывает его установленным приложением либо системным меню отправки.

Поддерживаются PDF, UTF‑8 TXT, JPEG, PNG и WebP. Лимиты по умолчанию составляют 10 МиБ на файл, 10 вложений на публикацию и 100 МиБ на загрузившего пользователя. Сервер определяет MIME и расширение по содержимому. Для PDF и изображений используется проверка сигнатуры формата. Загруженные объекты выдаются как вложения и не отображаются браузером на домене приложения.

## Доступ

- Личные файлы доступны владельцу задания.
- Групповые файлы и материалы доступны действующим участникам незакрытой группы. Проверка выполняется при каждой выдаче метаданных или нового скачивания.
- Вложения групповой публикации добавляет и удаляет её автор с действующим членством. Владелец или модератор может удалить всю чужую публикацию. Пользователь после выхода из группы лишается доступа к каждому её вложению, даже если раньше загрузил его.
- Группы, личные задания и материалы проверяются сервером. S3-бакет закрыт. Клиент получает метаданные и байты через API, без доступа к ключам объектов или S3-учётным данным.

## Сохранение и очистка

PostgreSQL хранит метаданные, права определяются родительской записью, а байты находятся в SeaweedFS. Запросы на загрузку ограничены по размеру и числу параллельных передач. API создаёт `PENDING`-запись, сохраняет объект под случайным ключом и после повторной проверки прав переводит запись в `READY`. Список показывает только `READY`. Квота учитывает ещё не очищенные загрузки.

При удалении отдельного файла запись переходит в `DELETING` и сразу скрывается. При удалении родительской записи внешний ключ обнуляется, чтобы сохранилась информация для удаления объекта. При архивировании группы или удалении группового задания связанный файл теряет доступ по правилам родителя. Все эти случаи и незавершённые загрузки старше 30 минут обрабатывает `files.cleanup`. Повтор физического удаления безопасен. Ошибка S3 сохраняет запись для следующего прохода. Пользователь после остановки передачи увидит фактический список при обновлении. Если сервер успел завершить запрос до отмены на клиенте, опубликованное вложение можно удалить обычной кнопкой.

Локальный SeaweedFS ранее создавал четыре тома для исходной коллекции, из-за чего новый бакет не получал свободного тома. Для локальной среды позволено восемь томов с прежним лимитом 128 МиБ на том и выделением по одному. Проверка готовности ожидает S3 и регистрацию volume server. В существующем окружении применяется обычный `pnpm infra:up` с сохранением именованного Docker-тома. Шаг `pnpm storage:init` создаёт бакет, если он отсутствует. Настройка роста использует [конфигурацию SeaweedFS master](https://github.com/seaweedfs/seaweedfs/blob/4.50/weed/server/master_server.go).

## Проверка

- `pnpm test:integration` проверяет реальный обмен с S3, прямые запросы разных участников, отказ после выхода из группы, ограничения и очистку объектов.
- `pnpm test:e2e tests/e2e/files.spec.ts` проверяет выбор файла, сохранение, скачивание и удаление через браузерный интерфейс.
- Для ручной проверки Android нужен пересобранный APK с `expo-document-picker`, `expo-file-system` и `expo-sharing`. Выберите фото или документ в системном окне, дождитесь публикации, откройте файл из карточки. Название и байты должны совпасть. Порядок запуска локального окружения в [README](../README.md).
