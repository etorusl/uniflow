# Вложения и материалы

Реализованы F1/F2. Схема и точный контракт: Prisma/OpenAPI; интеграционные сценарии — `apps/server/test/integration/files.test.mjs`, браузерные — `tests/e2e/files.spec.ts`.

## Форматы и ограничения

Разрешены PDF, JPEG, PNG, WebP и текст UTF-8 с расширением `.txt`. Сервер определяет бинарный тип по содержимому; текст проверяет на корректную кодировку, управляющие символы и HTML/SVG/XML. MIME из запроса не является доказательством типа. Проверка типа не является антивирусом или полной проверкой структуры документа. Превью, перекодирование и удаление EXIF в эту версию не входят. Камера не добавляется: пользователь выбирает существующий документ/фотографию через системный выбор файлов.

Максимум 10 МБ на файл, 10 вложений на публикацию, 200 МБ на автора загрузки и 500 МБ на группу. Пустые файлы отклоняются. Проверки размера действуют в multipart-парсере и сервисе. В квоты входят также незавершённые/ожидающие удаления записи до очистки. Резервирование квоты сериализуется транзакционной advisory-блокировкой пользователя, групповой квоты — блокировкой группы; это не блокирует пользовательскую строку и не образует цикл с FK при выполнении задания.

Имя файла очищается от путей и управляющих символов; UTF-8 имена multipart восстанавливаются из кодировки парсера. Ключ объекта — независимый случайный UUID, клиент не выбирает его и не получает в метаданных.

## Права и API

- `POST /files`: авторизованный multipart с `parentType`, `parentId`, `file`; родитель — существующее личное задание, групповое задание или материал. Пользователь добавляет файлы только в свои публикации; модераторство не разрешает править чужую публикацию.
- `GET /files`, `/files/{id}`, `/files/{id}/content`: новая проверка прав на родителя. К групповому файлу нужен действующий доступ в неархивную группу, независимо от автора загрузки. Удалённый материал/задание не даёт доступа к файлу.
- `DELETE /files/{id}`: владелец личного задания либо автор/модератор/владелец группы для групповой публикации. Повтор после завершённого удаления безопасен.
- У вложения только один фиксированный родитель; перепривязки и произвольные S3-ключи в API нет. SQL-ограничение запрещает несколько родителей. Нулевое число связей допустимо после физического удаления родителя до работы очистки.
- Бакет закрыт. Скачивание идёт через API, без публичных/подписанных URL: каждый новый запрос проверяет права. Ответ использует attachment, безопасное имя, nosniff и private/no-store. Скачивание, начатое при действующих правах, может завершиться после их отзыва; новые запросы закрыты.

## Согласование БД и S3

1. В транзакции проверяются родитель, права и квоты, создаётся PENDING с часом жизни.
2. Объект записывается в S3. Сервер ожидает запись до 90 секунд; клиентский транспорт загрузки — до 120 секунд, с прежней cookie/CSRF или bearer-защитой.
3. В новой транзакции повторно проверяются родитель и права, только PENDING становится READY. Потеря прав во время загрузки не создаёт доступного вложения.
4. Ошибка после резервирования оставляет DELETING либо PENDING, если БД временно недоступна. Эти записи подбирает очистка. Удаление сначала скрывает запись через DELETING, потом удаляет объект и метаданные; сбой S3 оставляет запись для повторной попытки.
5. Worker каждые пять минут обрабатывает до 100 записей: DELETING, просроченные PENDING, потерявшие родителя, вложения удалённых публикаций/архивных групп. Повтор безопасен; ошибка объекта журналируется по ID, запись сохраняется. Объекты не удаляются через публичный клиент.

POST означает новую загрузку. Если ответ потерян/отмена произошла после записи сервера, клиент предлагает обновить список до повторной попытки, а не обещает отсутствие файла. Прогресс в интерфейсе неопределённый, есть отмена. Список файлов загружается по раскрытию карточки; список задач не вызывает отдельный файловый запрос для каждой строки.

## Материалы

Самостоятельная модель Material, не Task. Любой участник публикует, автор редактирует, автор/модератор/владелец удаляют при действующем членстве. Редактирование проверяет версию и возвращает 409 при конфликте. Удаление мягкое, закрывает чтение текста/файлов и запускает последующую очистку объектов. Материалы не входят в статистику заданий. Лента имеет пагинацию по дате/UUID.

## Локальное хранилище

Для SeaweedFS установлен `volume.max=16`: исходное значение 4 заполнялось служебной коллекцией и не позволяло выделить тома для S3-бакета. Проверка готовности бакета не выявляла проблему; теперь интеграционные тесты выполняют настоящие PUT/GET/DELETE и проверяют запрет прямого анонимного доступа.
