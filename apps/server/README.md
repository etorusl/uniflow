# Сервер UniFlow

Модульный монолит на NestJS и TypeScript с PostgreSQL и Prisma. Сейчас каталог содержит структуру исходников; исполняемый сервер создаётся на [этапе 1](../../docs/development-plan.md).

## Каталоги и процессы

- `src/modules` — предметные модули: `auth`, `users`, `subjects`, `teachers`, `schedule`, `tasks`, `groups`, `files`, `materials`, `notifications`, `statistics`. Каждый каталог создаётся вместе с реализацией соответствующей функции.
- `src/infrastructure` — конфигурация и адаптеры PostgreSQL/Prisma, pg-boss, S3 API и SMTP.
- `src/common` — общие серверные механизмы, например формат ошибок и HTTP-контекст. Правила конкретного предметного модуля остаются внутри него.

Планируемые точки входа: `src/main.ts` для HTTP API и `src/worker.ts` для фоновой обработки. Это два процесса одной серверной кодовой базы. Worker не запускает HTTP API, а HTTP-процесс не забирает работы из очереди доставки. Схема Prisma и миграции будут находиться в `prisma/`.

Контракт REST API публикуется как OpenAPI и используется для генерации `packages/api-client`. Права проверяются внутри серверной прикладной логики для всех клиентов и транспорта. Файлы хранятся в закрытом объектном хранилище, очередь — в PostgreSQL.

Модульные тесты располагаются рядом с проверяемой логикой; интеграционные тесты сервера — в `test/`. Сквозные веб-сценарии находятся в корневом `tests/e2e`.

Команды запуска, миграций и проверок добавляются после создания исполняемого каркаса. Границы модулей и правила данных описаны в [архитектуре](../../docs/architecture.md).
